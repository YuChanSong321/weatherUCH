# 데이터 확보 현황 · 공백 보고서

이 문서는 "무엇을 어디서 받아야 하고, 지금 무엇이 막혀 있는가"를 한 장에 모은 것이다.
맨 아래 **체크리스트**만 따라가면 실측 전환이 끝난다.

> ⚠️ 이 문서에 적는 예시 URL의 인증 파라미터는 항상 `authKey=***` 로 마스킹한다.
> 스크립트도 로그·에러·보고서 어디에도 키 원문을 남기지 않는다
> (`common.py` 의 `mask_url()`).

### 0.1 키 없이 받을 수 있는가 — 없다 (2026-08-07 확인)

`apihub.kma.go.kr` 은 열리지만 **데이터 엔드포인트는 전부 401**이다.

```
GET /api/typ01/url/kma_sfcdd3.php?...   → 401 {"message":"유효한 인증키가 아닙니다."}
GET /api/typ01/url/stn_inf.php?...      → 401 (동일)
GET /api/typ01/url/fct_afs_dl.php?...   → 401 (동일)
```

웹 화면의 조회·다운로드도 같은 로그인을 쓴다(사이트 안내: 휴대전화 연락처 등록 없이는
API 이용 불가). **자동화된 익명 수집 경로는 존재하지 않는다.** 따라서 길은 두 가지뿐이다.

| 길 | 방법 | 스크립트 |
| --- | --- | --- |
| **A. 키로 자동 수집** | 루트 `.env` 에 `KMA_API_KEY=...` → 명령 한 번 | `fetch_asos.py` 외 2종 |
| **B. 직접 받아서 반입** | 로그인해 파일을 받아 `scripts/raw/` 에 두고 변환 | `ingest_raw.py` |

둘의 출력 스키마는 같다. 섞어 써도 된다(예: ASOS 만 A, SSP 는 B).

## 0.2 길 B — 직접 받아서 반입하는 절차

`apihub.kma.go.kr` 에 로그인해 아래를 받아 **`scripts/raw/` 에 정해진 이름으로** 넣는다.
확장자는 무엇이든 좋고(`.txt` `.csv`), API허브 응답을 그대로 저장해도 되고 포털 CSV 도 된다.
**컬럼 이름으로 값을 찾으므로 열 순서가 달라도 된다.**

| 파일명 | 받을 자료 | 없으면 |
| --- | --- | --- |
| `asos_daily.*` | 지상관측 > 종관기상관측(ASOS) 일자료 · 부산(159) · 3~5개 연도 | — (핵심) |
| `yearly.*` | 기후통계 연자료 (최근 30~40년) | 일자료에서 집계 |
| `normals.*` | 기후통계 월 평년값 1991–2020 | 일자료에서 집계 |
| `forecast.*` | 예·특보 > 단기예보 과거자료 | S1 3자 대결만 빠짐 |
| `warning.*` | 예·특보 > 기상특보 이력 | 관측에서 근사 |
| `blossom.*` | 지상관측 > 계절관측 (왕벚나무 개화) | S3 개화일 레이어만 빠짐 |
| `ssp.*` | 기후변화정보포털 SSP 전망 (`scenario,year,tavg[,low,high]`) | 근사 곡선 유지 |

```bash
python3 scripts/ingest_raw.py --dry-run   # 무엇이 바뀔지만 확인
python3 scripts/ingest_raw.py             # 교체
python3 scripts/sanity_check.py           # 값이 말이 되는지 검증
npm run build
```

일부만 넣어도 된다 — **있는 것만 교체하고 나머지는 그대로 둔다.** 교체된 파일은
`meta.source` 가 `KMA_MANUAL_DOWNLOAD` 로 바뀌고, 앱의 출처 표기가 그 항목만
"기상청 · 데이터명 · 수집일"로 자동 전환된다.

## 2. 공백 예상 ① — 과거 단기예보 아카이브

**S1 "당신 vs 기상청 vs 실제" 3자 대결이 여기에 걸려 있다.**

관측(정답)은 확실히 받을 수 있지만, **"그날 기상청이 사전에 냈던 예보"** 는 성격이
다르다. 예보는 발표 순간 지나가면 사라지는 자료라, 과거 발표분을 통째로 되돌려주는
API 가 없거나 보관 기간이 짧은 경우가 흔하다.

- 시도할 엔드포인트: `fct_afs_dl.php` (동네예보 구역), `tmfc1`/`tmfc2` 로 발표시각 범위 지정
- 확인할 것: **보관 시작 시점**. 2019년치가 나오는지, 최근 N개월만 나오는지.
- 현재 출제 풀은 2019–2023 이다. 보관 기간이 짧으면 출제 풀 자체를 최근으로 옮겨야 한다.

### 못 받을 경우의 선택지

| 안 | 내용 | 잃는 것 | 얻는 것 |
| --- | --- | --- | --- |
| **A. 지속성 베이스라인으로 대체** | "기상청" 자리에 *"어제와 똑같이 찍는 예보"* 를 세운다. 관측만으로 계산되므로 추가 데이터가 0 이다. | 실제 기상청과 겨루는 맛 | 교육적으로는 오히려 정직하다 — S1 이 가르치려는 게 정확히 "지속성이 어디까지 통하는가"다. 라벨만 `기상청` → `지속성 예보` 로 바꾸면 화면 구조는 그대로. |
| **B. 출제 풀을 보관 기간 안으로 이동** | 예보가 남아 있는 최근 기간으로 2019–2023 을 교체 | 40년 관측과의 연도 연결(S1→S2→S3)이 어긋날 수 있다 | 진짜 기상청 예보 유지 |
| **C. 3자 대결 제거** | S1 을 원래의 2자(당신 vs 실제)로 되돌린다 | "전문가도 틀린다" 라는 핵심 메시지 | 단순함 |

**권장은 A다.** 코드가 이미 "예보가 없는 날은 조용히 2자로 돌아간다"를 지원하므로
(`getPastForecast()` 가 `undefined` 반환), 부분 확보 상황도 그대로 굴러간다.

## 3. 공백 예상 ② — SSP 시나리오 전망 (S5 부채꼴)

기후변화 시나리오는 관측이 아니라 **모델 산출물**이라, 기상청 API허브(관측·예보
중심)가 아니라 **기후변화정보포털(climate.go.kr)** 소관일 가능성이 높다.

- API허브에서 확인할 것: 시나리오/전망 카테고리 존재 여부
- 없으면: 기후변화정보포털에서 **경상권(또는 남부권) 연평균기온 전망**을
  SSP1-2.6 / SSP2-4.5 / SSP5-8.5 세 시나리오로 조회 → 값 10개 안팎을 수동 입력

### 수동 입력 절차

1. climate.go.kr 에서 지역(경상권) · 변수(연평균기온) · 시나리오 3종 조회
2. `scripts/raw/ssp_gyeongsang.csv` 로 저장 (`scenario,year,tavg[,low,high]`)
3. `python3 scripts/fetch_asos.py` 실행 — CSV 가 있으면 자동으로 읽는다
   (`load_ssp_csv()`), 없으면 근사 곡선으로 폴백하고 `meta.source` 에 그 사실을 남긴다
4. 생성된 `future_ssp.json` 의 `meta` 를 아래로 맞춘다

```json
"_source": "manual (기후변화정보포털)",
"_provider": "기상청 기후변화정보포털",
"_dataset": "남한상세 기후변화 시나리오 · 경상권 연평균기온",
"_fetched_at": "2026-08-__",
"_license": "공공누리 유형 확인 필요"
```

> **주의**: S5 화면의 해설표는 이 JSON 의 값을 그대로 읽는다. 표에 함께 적히는
> "전 지구 평균 +1.8/+2.7/+4.4℃" 는 IPCC AR6 의 산업화 이전 대비 값으로 **기준이
> 다르다**. 수동 입력값이 어떤 기준인지(기준기간·지역) 반드시 `meta.baseline` 에
> 남길 것. 기준이 섞이면 화면이 조용히 거짓말을 한다.

## 4. 메타데이터 규약

실측으로 교체할 때 각 JSON 의 `meta` 에 아래를 넣는다. 앱의 출처 표기 화면
([Attribution.tsx](../src/scale/components/Attribution.tsx))이 **이 값을 그대로 읽으므로**,
빠뜨리면 화면에 "확인 필요"로 뜬다.

```json
"meta": {
  "source": "KMA_ASOS",
  "_source": "KMA API Hub",
  "_provider": "기상청",
  "_dataset": "종관기상관측(ASOS) 일자료",
  "_station": { "name": "부산", "stnId": 159 },
  "_fetched_at": "2026-08-07T00:00:00+09:00",
  "_license": "KOGL 제1유형 (확인 필요)"
}
```

`source` 가 `SYNTHETIC_DUMMY` 인 동안에는 앱이 "합성" 배지를 띄운다.
**이 배지를 코드로 지우지 말 것.** 합성값을 실측처럼 보이게 하는 것이 가장 위험하다.

### 5.1 계절관측 — 이름을 못 찾았다

아래 15개 후보를 전부 시도했으나 모두 `404 유효하지 않은 API 입니다`.

```
sfc_season / kma_season / season / sfc_seasonobs / kma_sfcseason / phenology
sfc_bio / kma_bio / sfc_nrm / kma_nrm / sfc_normal / kma_sfcnrm
sfc_mon / kma_sfcmm / kma_sfcyy
```

**추측을 그만두고 카탈로그에서 실제 이름을 확인해야 한다.** API허브 로그인 후
`지상관측 > 계절관측` 메뉴의 요청 URL 을 보면 파일명이 나온다. 그 이름만 알려주면
`fetch_blossom.py` 에 꽂으면 된다. 못 찾으면 기상자료개방포털에서 CSV 를 받아
`scripts/raw/blossom.csv` 로 두는 길도 있다(`ingest_raw.py`).

### 5.2 확인된 사실들

**지점 159 = 부산.** `stn_inf` 가 403 이라 이름으로는 못 봤지만 기후로 대조했다 —
한겨울 새벽 159번 **7.3℃** vs 서울(108) 2.6℃ · 강릉(105) 1.1℃, 한여름 오후는
159번 32.4℃ 로 서울 33.7℃ 보다 낮다. 남해안 지점의 서명이다.

**소급 1985년까지.** `kma_sfcdd3` 는 1985·1995·2005·2015년 모두 응답하고,
**1년치를 한 번에** 준다(365행/116KB). 40년 시계열을 40회 호출로 만들 수 있다.

**응답 인코딩은 CP949.** UTF-8 로 강제하면 주석 헤더가 깨진다.

**`kma_sfctm2` 는 `tm1`/`tm2` 를 무시한다.** 범위를 줘도 현재 시각이 돌아온다.
과거 조회는 `tm` 단일 시각만 된다.

### 5.3 파싱에서 실제로 걸린 함정 4개

실데이터를 넣어보고서야 드러난 것들이다. 전부 "조용히 틀린 값이 들어가는" 종류다.

| 함정 | 증상 | 조치 |
| --- | --- | --- |
| **중복 컬럼명** | 데이터 위 헤더가 `WS WS WS WS TA TA TA TA TA …` 로 축약·중복된다. `dict(zip(header,parts))` 는 같은 이름끼리 덮어써 엉뚱한 값을 넣는다 | 문서 순서 그대로 **위치(56컬럼)로** 읽고, 필드 수가 56이 아니면 그 줄을 버린다 |
| **풍향 단위** | `WD_MAX` 고유값이 5,7,9,…,34 — 16방위가 아니라 **36방위(×10°)**. 16방위로 읽으면 방위가 2배 이상 돌아가 S1 의 풍향 수업이 뒤집힌다 | `× 10` 으로 도 변환 |
| **결측 −9** | 비가 안 온 날 `RN_DAY = -9.0`. 그대로 두면 앱에 "강수 −9mm" 가 들어간다 | 강수·습도·운량·풍속은 −9 를 결측으로, **기온은 아니다**(−9 ℃ 는 실제 값일 수 있다) |
| **예보 행의 종결 표시** | 예보 응답 데이터 줄이 `…,흐리고 비,=` 로 끝난다. 헤더보다 칸이 하나 많아 전 행이 버려졌다 | 끝의 `=`·빈 칸을 떼고 비교 |

**앱 쪽에서도 하나 터졌다.** ASOS 에는 결측일이 있다(2023-05-24 는 `TA_MIN=-99` 라
통째로 빠졌다). `pickCase` 는 배열 인덱스로 "어제"를 잡고 있었으므로, 그 자리에서
"어제"가 실제로는 **이틀 전**이 된다 — S1 의 지속성 수업이 조용히 거짓이 된다.
네 날이 실제로 연속일 때만 출제하도록 고쳤다(1200회 출제 시험에서 불연속 0건).

**개인정보 주의.** 예보 응답에는 `MAN_ID`(예보관 ID)와 `MAN_FC`(예보관 실명)가
들어 있다. 파싱 대상에서 제외했고 출력 JSON 에도 남기지 않는다.

### 5.4 기상특보 — 부산 구역이 그 시절엔 없었다

S1 R3 배지("이날 부산에는 호우주의보가 있었습니다")를 위해 특보 이력을 받으려 했으나
**2019–2023 구간에는 부산 단독 특보구역이 존재하지 않는다.** 확인 과정은 이렇다.

1. 특보는 예보구역(`11H20201`)이 아니라 **별도 코드 체계**(`L…`/`S…`)를 쓴다.
   예보구역으로 조회하면 0건이 나온다.
2. 특보 현황 API(`wrn_now_data`)에서 코드→지명 매핑 238개를 얻었다.
   부산은 `L1082500`(동부) · `L1082600`(중부) · `L1082700`(서부).
3. **그런데 2023년 7~8월 전국 특보 8,968건에 이 세 코드가 단 한 건도 없다.**
   2025년 같은 기간에는 98건 나온다 — 그 사이에 신설된 것이다.
4. 부산지방기상청(STN 159)이 2023년에 다루던 29개 구역 중 2025년에 사라진 것은
   `L1080100`(70건) · `L1080300`(40건) 둘. 이 중 어느 쪽이 부산인지 갈라보려고
   두 가지를 시도했다.
   - **호우로 대조** — 발효일의 부산 관측 강수가 네 후보 모두 ~48mm(여름 평균 10.3mm).
     호우는 광역 현상이라 구분되지 않는다.
   - **폭염으로 대조** — 해안 부산은 33℃를 잘 안 넘으므로 내륙 경남 구역이면
     발효일에도 부산 관측이 낮게 나와야 한다. 결과: 네 후보 모두 평균 30℃ 내외,
     33℃ 이상 비율 3~15%. **어느 코드도 해안 부산의 서명을 보이지 않는다.**

→ 그 시기에는 부산이 경남 광역 구역에 묶여 있었다고 보는 편이 맞다.
**지어내는 것보다 비우는 쪽을 택했다.** `advisory` 필드는 비어 있고, 화면은 배지 없이
정상 동작한다(선택 필드로 설계해둔 것이 여기서 살았다).

선택지는 셋이다.

| 안 | 내용 | 대가 |
| --- | --- | --- |
| **A. 배지 없이 간다** (현재) | R3 는 "변동 큰 날" 필터로만 출제 | 배지 연출 하나가 빠짐 |
| **B. 출제 풀을 2025~ 로 옮긴다** | 부산 구역코드가 살아 있는 구간 | 풀이 1.5년으로 줄고, S1→S2→S3 의 연도 연결을 다시 잡아야 함 |
| **C. 관측에서 추정한다** | 일강수 30mm↑ → 호우주의보 등 | 기상청 특보가 아니므로 "추정"이라고 명시해야 하고, 그러면 배지의 힘이 빠짐 |

### 5.5 계절관측(벚꽃) — 엔드포인트 이름을 못 찾았다

15개 후보를 시도했으나 전부 `404 유효하지 않은 API 입니다`.

```
sfc_season / kma_season / season / sfc_seasonobs / kma_sfcseason / phenology
sfc_bio / kma_bio / sfc_nrm / kma_nrm / sfc_normal / kma_sfcnrm
sfc_mon / kma_sfcmm / kma_sfcyy
```

**추측을 그만두고 카탈로그에서 실제 이름을 확인해야 한다.** API허브에 로그인해
`지상관측 > 계절관측` 의 요청 URL 파일명만 알려주면 `fetch_blossom.py` 에 꽂는다.
또는 기상자료개방포털에서 CSV 를 받아 `scripts/raw/blossom.csv` 로 두면
`ingest_raw.py` 가 읽는다.
